# 文档审查优先级：排除的方向

状态：设计讨论中。延期功能记录于 [roadmap.md](roadmap.md)，不视为永久否决。

## 已排除

- 将产品主要目标设为漂亮图表或完整导航因果还原：核心目标是文档维护优先级，日志不足以保证因果还原。
- 将读取频率直接称为 agent 偏好、理解程度或注意力：可见事件不支持这些推断。
- 将相邻读取直接称为沿文档链接跳转：搜索、用户指定及上下文都可能是实际来源。
- 将未观察到读取直接判为无用文档：保留窗口与证据覆盖限制。
- 将配置推定的自动加载伪装为按文件确认的历史读取。
- 默认整批向模型发送原始聊天，或在报告页运行第三方 CDN 脚本：采用 architecture.md 中已确认的信任范围。
- 在本 skill 内自动修改目标仓库：本 skill 只发现问题并给建议。
- 默认将全仓 Markdown 都纳入开发文档审查，或让脚本凭目录名称判定长期/一次性用途：改由 agent 根据仓库语义选择范围，脚本执行明确目录。
- 多 harness 既往会话回溯作为默认动态来源：持久化格式、压缩/数据库、历史状态与抽样范围引入过大适配成本。改用本次受控任务的行为观测；这不证明历史分析无价值。
- 依靠试跑最终回答或要求其输出固定阅读清单来采集访问：回答不能替代行为证据，额外的观测提示会改变探索行为。临时解析器仅转换工具轨迹。
- 回滚当前工作树以寻找实验任务：从历史只读提取目标，确认适用于当前状态后再试跑。
- 临时解析器自行定义计数、分母与排序：固定脚本统一语义，临时适配仅转换证据格式。
