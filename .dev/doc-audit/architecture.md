# 文档审查优先级：架构约束

状态：产品设计已确认，v0.1 实现契约见本地规格 `.scratch/doc-audit/spec.md`；本文件保留职责与架构约束，尚无实现验证结果。

动态证据来自本次受控的只读实施前调查，不扫描既往会话来估算日常使用频率。实验结果只描述所选任务、当前环境下的文件访问，不能代表完整实施过程。

## 职责与信任范围

主 agent 选择任务并派发独立试跑子代理，按当前环境可获得的工具轨迹编写临时解析器。原始轨迹本地处理，不整批交给模型；语义审查沿用当前会话已有的模型服务信任范围，不承诺整个过程完全离线。

浏览器不加载第三方 CDN，固定前端资产随 skill 本地提供。目标仓库只读；生成报告、审查记录与修改目标文档是不同职责，后者不属于本 skill。

## 证据语义

静态引用、观测访问、自动注入分开表示。配置推定不升级为历史事实；缺少证据的来源显示未知。日志不能保证恢复完整文件访问，也不能证明模型理解了所读内容。

分层图解释文档导航结构及优先级依据。共享文档与循环引用允许存在，不能为了树形排版改写原始引用关系。

v0.1 的图连线来自静态引用，动态证据只提供实验中的文件访问统计，不生成读取转移边或重建导航序列。实际执行与继承上下文分开，调用与结果须可靠配对；顺序片段分析随桑基图延期。

## 运行能力预检

用户主动调用后，先根据当前工具接口和文档确认独立子代理、可取得的工具调用与结果、可停止的试跑生命周期，以及只读执行边界，不额外消耗正式试跑。轨迹可取得且试跑可控制时执行实验；能力不明确时先解决采集问题，不通过自报阅读清单补齐证据。

无法取得行为证据或无法满足只读执行边界时跳过实验，明确原因并继续静态审查。上下文隔离不完全但可以运行时，报告实际继承的上下文，不声称干净、无提示实验。

## 实验任务与上下文

任务来源依次为用户明确任务、当前有边界的未执行 ticket/plan、从历史只读提取且仍适用于当前工作树的任务目标、现场生成任务。不回滚或切换用户工作树；历史任务失去意义就跳过。

任务保留目标、验收条件及用户原本明确指定的文件；去掉前期解题过程和预设阅读路线，记录任务来源。每个试跑使用独立上下文，不提供审查者的热点、文档图或问题清单；保留真实工作所需的正常环境指导。隔离能力不足时在报告中说明。

试跑进行只读实施前调查，实际探索改动位置、约束与验证方法，不修改文件、不执行有副作用的命令。最终回答不规定格式，不要求列阅读清单或输出 JSON；不在试跑提示词中提及采集方式、解析器不依赖回答或类似观测要求。正常回答形式由任务决定，行为采集在试跑之外进行。

默认选择 3 个不同且边界明确的任务，每个独立试跑一次，数量可调整。按既定来源优先级选择，同一来源层级尽量覆盖不同目标；用户明确只分析单个任务时只跑该任务。报告展示任务及来源，声明小样本探索不代表完整开发需求。重复试跑与稳定性分析延期。

每次试跑默认最多 10 分钟，由调度层控制，用户可调整。任务提示中不添加统计用的文件数或步骤配额；超时停止该次试跑，保留已取得行为证据并标记中断，不要求补交阅读总结，不自动反复重试。

## 临时解析器与固定组装器

临时解析器只把可访问的工具调用与结果转换为标准化访问事件，保留实验任务标识、路径、访问类型和可回查的工具记录位置。子代理最终回答不作为文件读取证据，不据自报补造访问。

固定脚本负责输入校验、去重、指标、排序和报告组装；计数语义不交给临时解析器临场决定。无法获得工具轨迹时明确标记动态证据不可用，仍可执行静态审查。

## 文件访问统计口径

主要热点指标采用显式内容读取：明确返回文件内容才计入，局部读取也计入并保留局部标记。同一工具调用对同一文件最多计一次；多次调用可增加读取次数，同一试跑内的文件触达去重。

搜索命中片段单列为搜索曝光；文件名枚举、失败尝试和来源不明调用分别记录，不计为成功读取。自动注入单独展示，不计主动读取。指标展示分子及分母，不能以不完整证据宣称完整访问覆盖。

主要实验触达指标为正常结束且工具轨迹足以分析的试跑中，明确读取该文件的试跑数 / 有效试跑总数，优先显示分数，百分比辅助。有效试跑未读开发文档仍计入分母；无有效试跑时主要动态指标不可用，按静态规则排序。有效性依据运行状态与工具轨迹，不依据最终回答，也不保证任务方案正确。

中断或证据不完整试跑中已确认的读取单独保留，不混入主要指标的分子和分母。重复试跑的聚合不属于 v0.1。

## 证据保留

HTML 只包含任务简述、路径、访问类型、调用标识、读取范围及审查所需短证据，不内嵌完整聊天或工具输出。私有报告目录的标准化事件 JSON 保留计数依据和原始轨迹定位信息，不复制全部原始输出。

原始轨迹由当前环境管理，可能过期，不承诺永久回查。临时解析器用完删除，标准化事件保留至用户或系统清理报告目录。

## 运行栈

新 skill 要求 Python 3.12+，单独声明运行要求，不抬高全仓 Python 下限。不要求 Python 3.15、自由线程构建或多线程解析；先采用直接可测的处理流程，确认瓶颈后再优化。

Python 固定脚本负责静态扫描、事件校验、排序和报告服务；正式 Markdown 链接使用成熟解析库。前端采用本地固定版本的 Cytoscape.js 与 Dagre，预置 HTML/CSS/JS，无 Node/Vite 运行要求。具体依赖版本在实施前验证并固定。

## 渐进报告流程

先展示静态图与实验进度，实验数据完成后确定本次审查队列，再开始深审。审查结论逐步更新，开始后不因界面刷新不断重排任务。审查主 agent 和审查子代理的读取不混入试跑证据。

采用本地 HTTP 与短轮询，只更新数据而不重载页面，保留搜索、缩放及选中状态。服务仅覆盖本次扫描与审查，结束时生成自包含 HTML 快照并关闭服务，回报快照绝对路径。快照支持搜索、筛选和查看详情，不再更新。

报告放系统临时目录的随机私有子目录，不随脚本退出立即删除；提示系统可能清理，长期保留由用户复制。服务仅绑定本机，远程通过已有端口转发访问，不自动开放公网。

v0.1 仅支持本次运行内增加预算继续审查；运行结束后再次调用重新扫描并生成报告，不继承旧报告的已审状态。记录扫描时间及被审文件指纹；文档或已记录核查依据在审查期间变化时，对应结论标为需重新核查。
